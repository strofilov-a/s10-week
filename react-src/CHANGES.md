# Solo V4 · что изменилось после Solo V3 (11.11.2026)

Новые страницы:

- **`/solo/kazan`**, подготовка к Казанскому марафону 2 мая 2027. Это та же страница, что `/solo/plan`, в режиме Казани. Отдельного движка нет.
- **`/solo/kazan/start`**, промо-страница Казани, как `/solo/start` для Solo (добавлена 20.11.2026).

Структура и подключение те же, новых зависимостей нет.

## Какие файлы заменить

| Файл | В V4 |
|---|---|
| `solo-plan/SoloKazan.tsx` | **новый** — корневой компонент `/solo/kazan` |
| `solo-plan/engine.ts` | **изменился** — режим Казани; `mountSoloPlan(host, { mode: 'kazan' })` |
| `solo-plan/SoloPlan.tsx` | **изменился** — проп `mode?: 'solo' \| 'kazan'` |
| `solo-plan/storage.ts` | **изменился** — `storeFor(prefix)`: у Казани свои ключи `s10week.kazan.…`. `store` для Solo остался |
| `solo-plan/plan.css` | **изменился** — поле цели, заголовок Казани и шаги конвейера |
| `README.md`, `CLAUDE.md`, `CHANGES.md` | **изменились** |
| `solo-plan/api.ts` | **изменился** — `getLoose()` для `/apiapp/me` (22.11.2026) |
| `solo-plan/urlState.ts` | без изменений |
| вся папка `kazan-start/` | **новая** — `KazanStart.tsx` (корневой компонент `/solo/kazan/start`), `markup.ts`, `start.ts`, `start.css`, `fonts.css` (Roboto) |
| вся папка `solo-start/` | без изменений (`stage.ts` и `fonts.css` из неё нужны и `kazan-start/`) |

Если вы правили `engine.ts` у себя (пометки `// S10-LOCAL:`), перенесите правки в новый файл.

## Подключение

```tsx
import { SoloKazan } from './solo-plan/SoloKazan';
{path === '/solo/kazan' && <SoloKazan />}      // <SoloKazan overlay /> накрывает окно, как <SoloPlan overlay />
```

Маршрут ставится так же, как `/solo/plan`. Режим задаёт компонент, а не адрес: `<SoloPlan />` по адресу `/solo/kazan` откроет обычный Solo.

```tsx
import { KazanStart } from './kazan-start/KazanStart';
{path === '/solo/kazan/start' && <KazanStart />}   // точное совпадение адреса, иначе откроется /solo/kazan
```

`/solo/kazan/start` открывается без входа и запросов не делает, как `/solo/start`. Метатеги для оболочки — в `README.md`.

## Что делает страница

1. **Старт зафиксирован:** Казань, 2 мая 2027, 42,2 км. Дата предварительная: организатор её ещё не объявил. Вместо «Выбрать план» и генератора — поле цели, цель любая (22.11.2026): цель сохранённого плана, иначе введённая в этом браузере, иначе цель Казани из дневника, иначе 3:30. Объём берётся из плана на 3:00 (цели быстрее 3:15), на 3:30 (от 3:15 до 3:45) или на 4:00 (от 3:45), темпа — от самой цели.
2. **План встроен:** 24 недели от владельца. Цель задаёт темпа (от цели, пока атлет не задал свои во вкладке «Мои темпа»; свои темпа, сохранённые с планом, открываются и на другом устройстве) и объём лёгкого бега и длительных: ×1 / ×0,85 / ×0,7. Ключевые тренировки не меняются. В неделе старта нет лёгкого бега.
3. **Поздний вход:** если атлет начинает позже недели −21, две его первые недели идут с объёмом ×0,75 и ×0,9.
4. **Главный старт.** Если в дневнике другой главный старт или его нет, «Заполнить календарь» сначала спрашивает: «Казанский марафон 2 мая станет главным стартом вместо …». «Да» записывает день Казани главным стартом (`typtrain 6`, `main6 1`, тот же запрос `task.php`, что у «Сохранить старт»), потом заполняет. Без Казани главным стартом календарь не заполняется. Если Казань уже главный старт с другой целью, окно подтверждения говорит: «Цель на старт 2 мая сменится: 3:20 → 3:30.» Прежний главный старт заполнение не перезаписывает, даже со снятой галочкой «Не трогать…». «Вернуть как было» главный старт не возвращает и говорит об этом.
5. **Всё остальное как в Solo:** раскладка по дням, неделя «план / факт», календарь, вероятность, «Заполнить календарь», «Вернуть как было», перестройка по правилам и с ИИ (лимит 5 в сутки общий с Solo), Premium, «Мои темпа».
6. **Без входа** — блок «Подготовка к Казанскому марафону» и кнопка «Войти и начать» → `/login?back=<полный адрес>`. Запросов к дневнику нет.
7. **Конвейер для нового атлета (22.11.2026).** Пока в профиле нет казанской версии плана с заполненным календарём, вместо сводки и вкладок идёт по одному шагу: цель → дни недели → первая неделя → оплата 2 000 ₽ (`/money2?paysite=1&kazan=1`; шаг пропускается, если Premium оплачен до дня старта по `/apiapp/me` `subscriptionExpiredAt`) → «Заполнить календарь». Шаг хранится в `localStorage` `s10week.kazan.flow.<ID>`. Тренеру с `?id=` конвейер не показывается. Новый запрос: `GET /apiapp/me` (только на странице Казани, ответ читается с первой `{`, PHP-предупреждения перед ним не мешают).
8. **Вероятность (и в Solo).** Если форму не от чего считать (нет старта за 12 недель, прогноза S10 и своих темпов), вероятность считается от плана: кто выполняет его целиком, выходит на цель с вероятностью 70%. Цифра появляется после первой пробежки по плану, до неё — «Появится после первой недели тренировок». Слов «не от чего считать» больше нет.

## Данные

Новых форматов нет. Новый запрос один: `GET /apiapp/me` на странице Казани (дата оплаты Premium).

- **Версия плана** лежит в том же `studentPlans<ID>` и отличается полями `kind: 'kazan'`, `student.kazanGoal`, `student.kazanStart`. У атлета одна казанская версия. Активной она становится, только когда Казань — главный старт. После заполнения Казанью `/solo/plan` показывает «Казань 3:30» с тем же объёмом, атлет может выбрать там другую версию.
- **localStorage:** в режиме Казани все ключи с префиксом `s10week.kazan.` (`storeFor('kazan.')` в `storage.ts`), ключи Solo `s10week.…` не трогаются. Если вы меняли `storage.ts`, сохраните эту разницу.

## Для `/solo/plan`

Обычный Solo работает как в V3. Два отличия:

- Если активна казанская версия, он раскладывает её так же, как страница Казани (по её цели), а не как обычный план.
- Сгенерированный план теперь хранится в браузере (`localStorage` `s10week.fresh.<ID>`), пока не сохранён в профиль (22.11.2026). Без Premium в профиль ничего не пишется, и раньше атлет, вернувшись с оплаты, видел «План ещё не выбран» и генерировал план заново.

Всё прогнано на нашем стенде в Chromium.

- Сборка вашим стеком: webpack 5, ts-loader, style-loader и css-loader, React 17 `ReactDOM.render`. Строгая проверка TypeScript 4.9 с вашими настройками.
- Кабинет `/solo/plan`: 32 проверки, включая размонтирование и повторное монтирование.
- Казань `<SoloKazan />`: 38 проверок на React-сборке: поздний вход, вопрос о главном старте, версии, ключи localStorage отдельно от Solo, тренер с `?id=`, без входа, монтирование и размонтирование без хвостов.
- Промо-страница Solo: 41 проверка.
- Промо-страница Казани `<KazanStart />`: 63 проверки на React-сборке (компьютер, планшет, телефон; четыре блока сверху с картинками, ценой дня и учениками, круг садится на 2 мая, выбор цели, все кнопки на вход, размонтирование и повторное монтирование).
