## Отличия от b82aba6586

Владелец решил отдать вам текущую версию, а не `b82aba6586`. Что изменилось:

1. **Темпа: больше нет `NaN:NaN` в заданиях.** Сайт кладёт `{"err": "Нет данных для …"}` в `planresults.t`, когда не может посчитать прогноз. Раньше кабинет брал этот объект как темпа, и `T21+8` превращалось в `NaN:NaN`. То же было с версией плана, где заполнен только один темп.
   - Теперь источник темпов (прогноз S10 или план тренера) используется, только если в нём есть все четыре темпа.
   - Прогноз берётся из главного старта, иначе из первого результата, где он посчитан.
   - Темп читается в видах `4:30`, `04:30`, `0:04:30`, `4.30`, `430`.
   - Без темпа в тексте остаётся `T21+8`.
2. **Версии плана читаются с `&id=`** (`/apiweb/userparam.php?action=get&id=ID&param[]=studentPlans<ID>`), туда же, куда записываются. Раньше тренер, открывший атлета, читал свою строку. **Это меняет правило владельца при чтении** (см. «Кто владелец данных»).
3. **Без Premium план не сохраняется.** «Оформить Premium» и «Сохранить версию» сразу ведут на `/money`, в профиль ничего не пишется. В `b82aba6586` план перед уходом на оплату сохранялся.
4. **Лимит генераций ИИ: 5 в сутки** (по Москве) на вошедшего пользователя. Сюда входят «Сгенерировать план» и «Перестроить с ИИ». У кнопок видно «Осталось N из 5 на сегодня», на нуле они выключаются.
5. **«Добавить цель» и «Сбросить»** у главного старта (сводка вверху страницы).
   - **«Добавить цель»** открывает окно «Главный старт» с уже стоящим стартом. Если меняется только цель, день старта сохраняет свой текст, место и дистанцию.
   - **«Сбросить»** после вопроса удаляет день старта из дневника: пустая задача, как удаление в calc3. План остаётся без даты старта. Без старта на месте этих кнопок «Добавить цель».
6. **Возврат после входа.** «Войдите в S10» ведёт на `/login?back=<полный адрес страницы>`: сайт после входа возвращает только на полный адрес `https://s10.run/…`. В `b82aba6586` было просто `/login`.
7. **Шрифты промо-страницы** — свои woff2 вместо Google Fonts, начертания те же.

## Как это сделано: обёртка, а не переписывание

Обе страницы изначально написаны без React: кабинет рисует интерфейс HTML-шаблонами в одном корневом элементе, промо-страница — это готовая разметка со скриптом. Чтобы не менять ни поведение, ни алгоритмы, код **не переписан на React-компоненты**:

- **Кабинет.** Код релиза превращён в функцию `mountSoloPlan(host, opts)` в `engine.ts`. Она рисует страницу в переданный элемент и возвращает функцию очистки. Корневой компонент `SoloPlan.tsx` вызывает её в `useEffect` и очищает при размонтировании. Внутри кабинет по-прежнему рисует себя HTML-шаблонами, состояние хранится в замыканиях, а не в состоянии React.
- **Промо-страница.** `SoloStart.tsx` выводит разметку страницы (`markup.ts`) через `dangerouslySetInnerHTML`. Её скрипт перенесён в `start.ts` и `stage.ts`: он запускается в `useEffect` и полностью снимается при размонтировании.

Запросы к API, работа с localStorage и с адресом страницы вынесены в отдельные модули (`api.ts`, `storage.ts`, `urlState.ts`), их можно заменить при интеграции.

## Структура

```
solo-plan/
  SoloPlan.tsx   корневой компонент /solo/plan (проп mode: 'solo' | 'kazan')
  SoloKazan.tsx  корневой компонент /solo/kazan = <SoloPlan mode="kazan" />
  engine.ts      вся страница: mountSoloPlan(host, opts) → cleanup
  api.ts         get, post, generatePlanText: все запросы к сайту
  storage.ts     localStorage (ключи s10week.*, у Казани s10week.kazan.*)
  urlState.ts    чтение и запись ?id, ?tab, ?week, ?colors; popstate; уход со страницы
  plan.css       стили, все под .w-app
solo-start/
  SoloStart.tsx  корневой компонент /solo/start
  markup.ts      разметка страницы (строка)
  start.ts       скрипт страницы: mountSoloStart(root) → cleanup
  stage.ts       сцены прокрутки (GSAP ScrollTrigger, Lenis)
  start.css      стили, все под .s10-solo-start
  fonts.css      Jost и Golos Text (woff2 в data: URL)
kazan-start/
  KazanStart.tsx корневой компонент /solo/kazan/start
  markup.ts      разметка страницы (строка)
  start.ts       скрипт страницы: mountKazanStart(root) → cleanup (сцены из solo-start/stage.ts)
  start.css      стили, все под .s10-kazan-start (шрифты Jost и Golos Text из solo-start/fonts.css)
  fonts.css      Roboto (woff2 в data: URL) для трёх блоков сверху
README.md, CHANGES.md, CLAUDE.md
```

`engine.ts`, `plan.css`, оба `markup.ts`, оба `start.css` и `fonts.css` сгенерированы скриптом из исходников релиза. Сам скрипт лежит в нашем репозитории (`deploy/react-src.cjs`). Править их можно, но при следующей нашей версии мы пришлём их заново целиком.

## Подключение

```tsx
import { SoloPlan } from './solo-plan/SoloPlan';
import { SoloKazan } from './solo-plan/SoloKazan';
import { SoloStart } from './solo-start/SoloStart';
import { KazanStart } from './kazan-start/KazanStart';

// где-то в вашем роутере
{path === '/solo/plan'  && <SoloPlan />}
{path === '/solo/kazan' && <SoloKazan />}
{path === '/solo/start' && <SoloStart />}
{path === '/solo/kazan/start' && <KazanStart />}   // точное совпадение: /solo/kazan/start — не /solo/kazan
```

- **Независимость страниц.** Каждая страница — отдельный корневой компонент. При импорте ничего не монтируется. `SoloStart` и `KazanStart` не делают запросов: в `start.ts` и `stage.ts` нет ни одного `fetch` и нет обращений к кабинету.
- **Режим задаёт компонент, а не адрес.** `<SoloKazan />` включает Казань, `<SoloPlan />` по любому адресу — обычный Solo.
- **`<SoloPlan overlay />`.** Кабинет накрывает всё окно (`position: fixed`), как в отдельном релизе поверх `#root` сайта. По умолчанию `overlay` выключен, и кабинет рисуется на своём месте.
- **Webpack.** Нужны правила только для `.tsx?` (ts-loader) и `.css` (`style-loader` + `css-loader`). Шрифты лежат внутри CSS как `data:`, отдельное правило для файлов шрифтов не нужно. Для `import './x.css'` в проекте нужна декларация `declare module '*.css';`, если её ещё нет.

### HTML-оболочка и метаданные

- **`/solo/plan`.** Шрифт Roboto 400/500/900 из `/t5`, как у `/calc3`: кабинет его не подключает сам. Заголовок вкладки «Моя неделя · S10.run» кабинет ставит сам (`document.title`), на `/solo/kazan` — «Казанский марафон · S10.run». Оболочка у `/solo/kazan` та же, что у `/solo/plan`. Оболочка релиза — `solo.html`, в ней `theme-color #004aad` и cookie-баннер сайта.

  - `<title>S10 Solo — план до старта</title>`;
  - `meta description`;
  - `og:title`, `og:description`;
  - `theme-color #EEF1EF`;
  - `viewport` с `viewport-fit=cover`.

  Тексты — из `solo-start.html` релиза.
- **`/solo/kazan/start`.** То же самое, тексты из `kazan-start.html` релиза: `<title>Казанский марафон 2027 — план подготовки · S10 Solo</title>`, `meta description`, `og:title`, `og:description`, `theme-color #EEF1EF`, `viewport-fit=cover`.

## Хранение

**На сервере** (`stravauserparam` через `/apiweb/userparam.php`):

- `studentPlans<ID>` — JSON-список версий плана атлета `ID`.
- В активной версии: `student.layout` (роли Пн–Вс), `student.volume`, темпа `t5…t42`, `student.easy`, `student.noRace`, `filled {at, from, to}` и `undo`.
- Версия Казани — в том же списке, с полями `kind: 'kazan'`, `student.kazanGoal` (цель) и `student.kazanStart` (неделя первого заполнения, для мягкого входа). Одна на атлета; активной становится, только когда Казань — главный старт.
- `soloGen` в строке **вошедшего** пользователя — `{"d": московская дата, "n": генераций в этот день}`, лимит 5.
- `studentMainStart` и `planTemplates` кабинет только читает.

**В localStorage** (`storage.ts`, к каждому ключу добавлен префикс `s10week.`, на `/solo/kazan` — `s10week.kazan.`; значение — JSON):

| Ключ | Что |
|---|---|
| `tab` | Последняя вкладка |
| `layout`, `fillSpan` | Раскладка дней; «2 беговые недели» или «До старта» |
| `palette` | Палитра (видна только с `?colors`) |
| `plan.<ID>` | Выбранный план атлета |
| `paceSrc.<ID>`, `paceOwn.<ID>`, `paceGuess.<ID>` | Откуда темпа, свои темпа, темпа из окна старта |
| `noRace.<ID>` | «Отсутствует»: план без соревнования |
| `undo.<ID>` | Копия записи для отмены |
| `goal.<ID>` | Только у Казани: выбранная цель |

При загрузке активная версия с сервера важнее того, что лежит в браузере.

**В адресе** (`urlState.ts`): `?id=` (тренер открывает атлета), `?tab=plan|paces`, `?week=YYYY-MM-DD`, `?colors`. Кабинет пишет `tab` и `week` через `history.pushState`/`replaceState` и слушает `popstate`. Если адресом владеет ваш роутер, замените четыре функции в `urlState.ts`.

## Кто владелец данных

- **Атлет** — `?id=` из адреса, а без него — вошедший (`me.id` из `/apiweb/student/self/info/`). Если id не свой, страница открыта тренером: окна первого старта и кнопок «Добавить цель» и «Сбросить» нет.
- **Дневник, старт, прогноз, запись дней, версии плана** (чтение и запись) — всё с `id=ID` атлета.
- **Счётчик генераций** (`soloGen`) — у вошедшего: генерации тратит тот, кто нажимает кнопку, в том числе тренер на странице атлета.

В `b82aba6586` версии плана читались без `&id=`, то есть из строки вошедшего. Тренер, открывший атлета, не видел версий, которые сам ему сохранил: запись уходила в строку атлета. Мы это исправили (пункт 2 в «Отличиях»). Если для совместимости с calc5 нужно старое поведение, достаточно убрать `&id=${id}` в трёх чтениях `studentPlans` в `engine.ts`.

Права на запись проверяет сайт, кабинет их не проверяет. Без Premium кнопки записи выключены, а «Заполнить календарь» и «Сохранить версию» ведут на `/money`.

**Лимит генераций — защита только на стороне браузера.** Генератор `https://s10.run/t7/plan-templates/public/api/generate.php` открыт без авторизации и своего лимита не имеет. Остановить того, кто вызывает его напрямую, может только лимит на нём самом.

## Коротко о расчётах

- **Даты.** «Сегодня» — московская дата из `nowmsk`: это unix-время, к нему прибавляются 3 часа. План накладывается на даты от конца: неделя −1 — неделя старта, неделя −n начинается за n−1 неделю до неё. Без старта («Отсутствует») конец плана ставится так, чтобы его начало попало на ближайшую беговую неделю S10 из `dselect` (calc.php: среда этой и следующей недели). Прошлые дни и сегодня не записываются никогда. Дни, где задача уже есть, остаются, пока не снята галка «Не трогать».
- **Объём.** Каждая неделя плана масштабируется отношением выбранного объёма первой недели к объёму первой недели мастер-плана. Темпа вида `T21+8` перед записью переводятся в мин/км.
- **Перестройка по правилам.** Касается недель со следующего понедельника.
  - Если за 2 недели пробежано меньше 80% плана: следующая неделя = средняя за 2 недели +10%, дальше +10% в неделю, но не меньше 40% плана и не больше плана. Длительные сокращаются вместе с объёмом, ключевые тренировки не меняются.
  - Если больше 110% плана: до +5% к плану в пределах `maxweek`.
  - Пропущенная ключевая тренировка переносится на свободный день, рядом с которым нет тяжёлых дней.
  - Систематически быстрые или медленные ключевые тренировки сдвигают все темпа на 3–10 с/км.
- **Перестройка с ИИ.** Генератор calc4 переписывает те же недели по подсказке. Записываются только дни, которые всё ещё совпадают с текущим планом.
- **Отмена.** `undo` хранит, каким был каждый записанный день до записи. «Вернуть как было» восстанавливает дни, которые с тех пор никто не менял, а заодно прежнюю версию плана и темпа. День, пустой до записи, очищается (`{typtrain:0, task:'', prekm:0}`).
- **Вероятность достижения цели.** Форма сейчас (последний старт за 12 недель по Ригелю k=1,06, иначе прогноз S10, иначе темпа) и форма в день старта с поправкой на подготовку за 6 недель. Из них по нормальному распределению получается 1–99%.

## Ограничения и отличия от релиза

- **Кабинет внутри не на React.** Интерфейс рисуется HTML-шаблонами в одном элементе, состояние — в замыканиях `engine.ts`, обработчики навешаны делегированием на корень.
- **Типизация в `engine.ts` в основном `any`.** Параметры функций и пустые начальные значения получили тип `any`, места, где релиз читает значение без проверки на `null`, помечены `!` или `as any`. Код JavaScript при этом не изменился. Исключение — одна замена `[...new Set(x)]` на `Array.from(new Set(x))`: в ES5 без `downlevelIteration` первая не работает.
- **Промо-страница: разметка через `dangerouslySetInnerHTML`** (`markup.ts`), без JSX.
- **Стили промо-страницы перенесены с `html`/`body`/`:root` на корень `.s10-solo-start`.** Классы `js` и `is-smooth`, которые релиз ставил на `<html>`, ставятся на корень. На время показа страница сама задаёт `scroll-behavior` у `<html>` (`smooth`, или `auto` при Lenis и reduced motion) и `overscroll-behavior: none` у `<body>` при Lenis, а при размонтировании возвращает прежние значения. Анимации `race-pop`, `race-num` переименованы в `s10ss-race-pop`, `s10ss-race-num`.
- **Lenis и `lagSmoothing(0)` у тикера GSAP глобальны, пока промо-страница открыта.** При размонтировании Lenis уничтожается, а тикеру возвращается `lagSmoothing(500, 33)` (значение GSAP по умолчанию).
- **`Stage.split` из `stage.js` не перенесена:** страница её не использует. Глобальные `window.Stage` и `window.Scenes` заменены модулями.
- **Шрифты промо-страницы — свои woff2 вместо Google Fonts.** Начертания те же.
- **Кабинет меняет `document.title`** и при открытом меню ставит `overflow: hidden` у `<html>`. При размонтировании возвращаются прежние фон и `overflow` у `<html>`, а заголовок — нет.
- **Запросы, начатые до размонтирования, завершаются.** Запись дней в дневник на середине не обрывается, но после размонтирования страница больше ничего не рисует.
